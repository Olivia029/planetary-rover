# planetary-rover — Requirements and where the code meets them

Planetary rover on a 6×9 grid with heights. Every row says what the practice asks for, **where in the project it is met** (`file::class.function`), which tests check it and the command that shows it. Figures are from the delivered project: 162 states, 126 (origin, destination) pairs, 48 tests.

## Table 2 — The common rules of the themes

| Rule | What it says | How this project meets it | Where |
|---|---|---|---|
| Map | `data/map.txt`, one row per line: `.` free, `#` obstacle, `~` hazard, one capital letter per place. | 6×9 map with rocks, craters and the places `A` antenna, `B` base, `M` rock sample. | `data/map.txt`, `src/world.py::World.load` |
| Actions | 0 ↑, 1 →, 2 ↓, 3 ←; against the edge or an obstacle the robot stays. | Same four actions; edge, rock and a climb above 1 leave the rover in its cell. | `src/world.py::MOVES`, `World.move` |
| Rewards | −1 per step; +20 on the destination; −50 on the hazard. | Same values. The hazard is a crater **or a fall above 2** (heights). | `src/rover_env.py`: `STEP_REWARD`, `GOAL_REWARD`, `HAZARD_REWARD`, `RoverEnv.step` |
| End | `terminated` on destination or hazard; `truncated` at 100 steps. | Same; the limit is set with `max_episode_steps=100`. | `src/rover_env.py::RoverEnv.step`; `gym.register(..., max_episode_steps=MAX_STEPS)` |
| Start | `reset` draws a random destination and free cell; `run_policy` gives them. | `reset` uses `self.np_random`; with `options` (`start`, `destination`) it starts there. | `src/rover_env.py::RoverEnv.reset`, `src/tools.py::run_policy` |
| State | destination × (rows × columns) + row × columns + column; destinations in alphabetical order. | `A` 0, `B` 1, `M` 2; 3 × 54 = **162** states; the table has 162 rows and 4 columns. | `src/rover_env.py::RoverEnv.state` |
| Interface | An own Gymnasium environment: `gymnasium.Env` subclass with `reset` and `step`; `register`, `make`, `check_env`. | `RoverEnv(gymnasium.Env)`, `Discrete(162)` and `Discrete(4)`, registered as `RoverGrid-v0`; `check_env` runs on `gym.make(...).unwrapped`. | `src/rover_env.py`, `tests/test_env.py` |

> **Additions to the standard statement.** (1) **Heights**: `data/heights.txt` gives a level 0–9 to every cell. A climb above `MAX_CLIMB = 1` is blocked and a fall above `MAX_DROP = 2` is a hazard (−50 and end), like a crater; it is all in `src/world.py::World.move`, and the reference route (BFS) is directed. (2) **Own map**: a 6×9 map designed for this project, with places `A`, `B` and `M`. (3) **Viewer**: `src/viewer.py` writes `results/viewer.html` (saved results, no model) and `src/serve.py` adds a live chat with `qwen3:4b` through Ollama. The rest of the common rules is unchanged.

Test names are those listed by `uv run pytest --collect-only -q` (48 tests). Code references have no line numbers on purpose, so they stay valid if a file is edited.
